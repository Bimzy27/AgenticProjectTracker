# Terminal processes are owned by the main process, not the renderer's tab lifecycle

A Terminal instance's shell process must keep running when the user switches to another tab or another project, so a long `claude` session or a build started in a Terminal isn't killed by navigation. We decided the main process owns each PTY (keyed by terminal id, same shape as `RunOrchestrator` owning agent runs independent of what's on screen) and buffers its output; the renderer's terminal component attaches/detaches to a live process rather than owning its lifetime. This does not extend across app restarts: an actual OS process cannot survive the app quitting, so Terminals are ephemeral on restart with no persisted metadata - deliberately, since restoring placeholders for processes that can't actually be restored would only add confusing "is this real or a stub" states for no benefit.
